# Ionicons Broken Glyphs On Railway Production

## Summary
- **Issue:** Bottom-bar Ionicons rendered as fallback boxes/glyphs on Railway production.
- **Local status:** Icons rendered correctly on localhost.
- **Impact:** Navigation icons appeared broken in production UI.
- **Resolution:** Normalize vector-icon font asset URLs during web export to stable `/assets/fonts/...` paths.

## Symptom
- On production, all four bottom-bar icons showed a fallback glyph (box / incorrect character).
- This was reproducible only in Railway deployment, not local dev.

## What We Tried
1. Fixed unrelated TypeScript build issue (`asObject` missing import) to unblock deploy.
2. Confirmed `@expo/vector-icons` existed in `apps/client/package.json`.
3. Added explicit icon font load in app layout:
   - `Ionicons.loadFont()`
   - Then gated render until the font load promise completed.
4. Added `expo-font` as a direct dependency in `apps/client/package.json`.
5. Added a static-server fallback route for odd asset path normalization.

These were useful hardening steps but did not fully eliminate the production-only breakage by themselves.

## Current Icon Load + Serve Flow
- Icons are imported from `@expo/vector-icons` (Ionicons) in UI components.
- App startup triggers `Ionicons.loadFont()` in `app/_layout.tsx`.
- Web build is generated by:
  - `expo export --platform web --output-dir dist`
- Production serves static files from:
  - `apps/client/dist`
  - via `tools/static-server.js`

## Root Cause (Practical)
Expo web bundle referenced font assets under pnpm-flavored paths, e.g.:

`/assets/__node_modules/.pnpm/@expo+vector-icons.../Fonts/Ionicons.<hash>.ttf`

In production, these paths were fragile (proxy/path normalization behavior). Result: font fetch mismatch/failure and fallback glyph rendering.

## Actual Fix
Added a post-export normalization step that:
1. Copies vector icon font files into `dist/assets/fonts/`.
2. Rewrites web bundle font URLs from pnpm-internal paths to stable public paths:
   - from `/assets/__node_modules/.pnpm/.../Fonts/*.ttf`
   - to `/assets/fonts/*.ttf`

### Files Added/Changed
- Added script:
  - `apps/client/scripts/normalize-vector-icon-font-paths.cjs`
- Updated web build command:
  - `apps/client/package.json`
  - `build:web` now runs:
    - `expo export ...`
    - then `node scripts/normalize-vector-icon-font-paths.cjs`

## Verification
- After rebuild, bundle references changed to `/assets/fonts/*.ttf`.
- Railway production now renders Ionicons correctly.

## Notes / Preventive Actions
- Keep `pnpm-lock.yaml` committed for deterministic dependency resolution.
- For Railway web deploys, ensure build/start commands target web static output:
  - build: `pnpm build:web`
  - start: `pnpm start:web`
- Prefer stable exported asset URLs over package-manager-internal paths in production.
